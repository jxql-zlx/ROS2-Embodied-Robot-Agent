## 详细执行清单

### 1. 统一接近流程的停止确认和准入门禁（高，待执行）
- 范围：`robot_agent_node.py`、`approach.py`、`executor/flash_executor.py`。
- 将 ApproachController 的成功停车、失败停车接入 node 提供的统一回调，避免绕开命令串行锁与准入状态。
- 停止被拒、发布异常、反馈超时、匹配 ID 缺失时，用结构化结果表达“停止未确认”，并保留门禁。
- 明确取消中由哪个流程负责停车，避免 approach 与取消线程重复发布而互相覆盖反馈。
- 梳理 simple/hierarchical 的运动完成等待，明确由一处负责，避免 simple 路径重复等待。
- 验收：两种模式的 approach 停止失败后新任务均被拒；显式重试确认成功后恢复；成功接近正常退出。

### 2. 修复取消全过程的门禁归属和释放时机（高，依赖 1，待执行）
- 为取消操作保留 task ID、任务代次、停止操作代次/归属，明确谁有权释放门禁。
- Nav2 取消的初次 stop 只确认初次制动；直到 Nav2 终态、原任务结束以及最终 stop 确认均完成，才能释放取消门禁。
- 修复“Nav2 先结束 → 初次 stop 清门禁 → 新任务进入 → 最终 stop 停掉新任务”的窗口。
- 修复普通运动失败自动 stop 与显式 cancel 同时进行时，一个操作清除另一操作门禁的问题。
- 确认等待在任务准入锁之外；不能靠全程占用任务锁让测试通过。
- 验收：使用事件屏障控制线程交错，覆盖最终 stop 前、确认中、失败后、新任务代次变化；未结束的取消不得放行新任务。

### 3. 固定动作 ID，并保留足够的状态回执（高，依赖 1–2，待执行）
- 在命令提交时固定 command_id，move/rotate/approach 的等待显式传入它，避免等待目标依赖可变的 latest_command_id。
- 解决 `_latest_status` 单槽覆盖：按命令 ID 保留有数量/时间上限的终态回执，或提供等价的独立等待对象。
- 记录接收顺序/来源时间，防止迟到旧状态覆盖已确认终态；节点重启或时钟重置时清理旧会话数据。
- 对缺失 ID 的确认保持失败关闭；缓存必须有清理上限，不能无限增长。
- 验收：A/B 状态紧邻、反序、重复、错 ID、迟到 error、先收到回执后开始等待、第一条状态尚未到达。

### 4. 修复激光扫描的源时间与时钟域（高，待执行）
- 范围：`ros2_robot_tool.py`、相关 launch/仿真启动参数、`test_front_range.py`。
- 同时检查消息接收年龄和 `LaserScan.header.stamp` 的源年龄，拒绝积压旧帧、过度未来帧、零时间戳。
- 在仿真中确认工具节点使用 `/clock`；不能把仿真时间戳直接减去墙上时间。
- 区分乱序扫描与真实时钟回退：不能只因一条较小 stamp 就认定新时钟会话。
- 在同一锁内读取 scan、时间戳和接收时间，避免旧 scan 搭配新接收时间。
- 验收：新收到的旧帧仍 unavailable；重复/乱序帧不能凑出三次确认；仿真重启后新会话可恢复。

### 5. 收紧接近阶段的动作与目标约束（高，依赖 1、3、4，待执行）
- 范围：`approach.py`、`action_plan.py`、相关 LLM 与 approach 测试。
- 给 plan_motion 的输出建立阶段允许列表：接近阶段不能派发 navigate、递归 approach 或视觉查询动作。
- 校验数值类型、有限性、速度、运动方向、持续时间；不能把错误的零/负时长静默变为有效运动。
- 检查只有前向测距时的倒车/侧移请求，依据已支持的反馈能力拒绝未覆盖方向。
- 选择真正匹配目标的检测项，方向与到达判断使用同一目标；重观察每一轮都重新校验名称和 found。
- 核对最短 0.1 秒步长与剩余净空：含控制周期和制动余量，余量不足直接停止，不靠最小时长强制前进。
- 验收：错误动作、NaN/Inf/布尔值、负时长、目标列表首项不匹配、目标消失或换对象时，不发未授权运动。

### 6. 修复 simple / hierarchical 取消仿真脚本（高，可先独立执行，待执行）
- 范围：`scripts/navigation_cancel_scenario.py`、`scripts/wsl_navigation_cancel_scenarios.sh`。
- simple 使用纯导航任务；hierarchical 保留“导航→找物→接近”组合任务。
- 按模式解析 action_json：simple 是动作对象，hierarchical 是阶段结果列表；不能统一迭代并调用 item.get。
- 层级模式检查依赖阶段未执行，避免只依赖固定任务编号；两种模式均验证目标 UUID、CANCELED 和后续导航。
- 若任务提前失败，立即输出真实服务响应，避免继续等待一个不会出现的 Nav2 目标。
- 清理时取消当前仍活动的请求，并等待对应 future；不能取消 follow-up 却等待最初任务的 future。
- 验收：默认同时运行 simple/hierarchical 能通过；故意注入输入/结果格式错误时诊断明确且退出非零。

### 7. 完善按 task ID 取消、重试与客户端超时（高，依赖 2，待执行）
- 原任务 finally 清 active ID 后，保留尚未完成的取消归属；允许相同 UUID 重试确认停止，拒绝其他 UUID 释放门禁。
- 复现“取消先到、执行请求后被处理”的情况；明确迟到请求是取消、拒绝还是需要重试，避免已回复取消成功却继续执行。
- 明确重复 task ID 的行为；若需去重，采用有容量和过期策略的记录，不缓存无限历史。
- 对齐客户端 8 秒等待和服务端初次确认/导航终态/最终确认的总期限；传播单一 deadline 或明确各阶段超时。
- 区分任务已结束、取消处理中、停止已确认、结果未知；topic 仅报告调用一次发布，不能宣称可靠送达或业务 exactly-once。
- 验收：旧 UUID 不停新任务；同 UUID 可恢复未完成取消；服务不可用、超时、future 异常、重复提交有明确退出码和诊断。

### 8. 补齐简单动作与分层计划的逐动作校验（中，依赖 5，待执行）
- 范围：`action_plan.py`、`planner/task_schema.py`、`llm.py`、executor。
- 在模型输出入口校验每种动作的参数类型、范围和必填字段；拒绝字符串数值、布尔值、未知参数和无效导航 timeout 等。
- 对直接构造的 ActionPlan、infer 生成的动作、replan 恢复计划沿用同一校验入口。
- 保留底层控制器验证，确保新入口的严格校验不影响合法的默认配置和 stop 动作。
- 检查复用 HierarchicalAgent/TaskManager 时前次失败或取消的 pending task 是否污染下一次任务；先复现再决定清理位置。
- 验收：非法输入在任何命令发布之前失败；恢复计划不能绕过校验；合法 mock 计划仍通过。

### 9. 明确“接近到位”和“物理停车”的证据边界（中，依赖 1、4、5，待执行）
- 当前前向 ±10° 最近回波是净空距离，不能证明是杯子的表面距离。无关联证据时不得输出“目标距离已确认”。
- 先修正结构化结果与 UI/CLI 文案：区分达到净空阈值、被障碍阻挡、目标关联未知、目标到达。
- RobotStatus stopped 代表控制层已处理 stop 并发布零速度，不能直接当作轮子已经静止；将确认类型写入结果。
- 若任务契约要求物理停车，接入新鲜且连续的 odom 低速/位姿窗口，包含数据中断与时间跳变；使用独立配置阈值。
- 验收：目标居中但近处有无关障碍不能报告目标到达；odom 丢失或仍在运动时不能报告物理静止已验证。
- 精确目标深度/相机—雷达标定另作后续阶段：先调查现有传感器和变换是否足够，不在本批直接扩展重大架构。
